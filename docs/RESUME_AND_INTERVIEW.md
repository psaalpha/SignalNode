# 简历形成条件与面试证据

项目名建议：基于STM32与FreeRTOS的信号采集分析终端。

当前已完成SPL目标代码、编译链接和主机验证，尚未完成硬件联调。原简历/已交付简历未被本项目修改；不能提前把DMA、RTOS、Modbus上板、长时间稳定运行或BFSK硬件实测写成已完成。

## 完成后简历的四个信息位置

以下是内容结构，不是当前可以直接粘贴的完成陈述。括号位置需由实际实现与测量填入，验证失败也应保留真实结果。

1. 系统：实际MCU、连续采样方式、采样率、窗口/步长、任务分工。
2. 信号：滤波/RMS/FFT、窗归一化、校准条件与实际误差。
3. 通信：实际支持的RTU功能码、寄存器快照、原始数据协议、异常恢复。
4. 验证：实际板上耗时、栈/内存占用、连续运行时长、丢块和故障注入结果。

如果只完成P1/P2，简历就只写这些部分；不需要为了名词齐全而加入未完成的P3/P4。

## 值得准备的面试问题

- 为什么8kSa/s、1024点、512步长？观测窗、更新率、估计误差与双音分辨率分别是什么？
- 软件定时采样为什么会受任务调度影响？硬件定时触发解决了哪部分问题？
- DMA循环写入时，任务如何取得不会被覆盖的数据？池满时丢哪一块，如何让电脑知道？
- 为什么重叠窗口中的样本不能反复经过有状态IIR？丢块后为什么要清空历史？
- 为什么RMS不直接在加窗数据上算？正弦幅值与频段功率的窗补偿为什么不同？
- 为什么CMSIS RFFT的out[0]和out[1]不能一起取复数模？
- 637.3Hz样例为什么频率更接近了但幅值仍低？什么条件下插值会失效？
- 6500Hz为何出现在1500Hz？模拟抗混叠和数字低通分别放在哪里？
- RS485与Modbus是什么关系？UART IDLE、DMA TC和USART TC各代表什么？
- 19200/115200是否足以持续发原始波形？怎样计算起止位、校验位、协议头和负载占用？
- 为什么volatile不能让一组寄存器变成同一时刻的快照？
- 为什么192KB RAM不代表DMA能访问所有192KB？
- 符号边界已知的BFSK判决，与能从任意位置开始接收的完整接收机，差哪些模块？

准备证据：原理图/接线图、配置文件、输入设置、原始CSV、数值对照、时序截图、map、栈水位、异常记录与对应提交。能沿着一份原始数据解释到最终结果，是本项目最有价值的面试材料。
